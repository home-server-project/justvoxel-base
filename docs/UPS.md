# UPS backend contract

The HWS variant uses native NUT. The Management Agent owns `/etc/ups` and the deployment's NUT service enablement. `GET /v1/ups` reports the selected source, effective NUT mode, protection and sharing state, service state, and allowlisted `upsc` metrics. It never returns monitor or sharing passwords.

`POST /v1/admin/ups/source` accepts the existing `mode`, `host`, and `port` fields. A remote source remains usable for read-only status without shutdown credentials. `ups_name` is optional when the remote server reports exactly one UPS; a server with several UPS devices requires an explicit selection before protection can be enabled. For local NUT management, the caller must explicitly supply `ups_name`, `driver`, and `device_port` together. Hardware discovery and a choice UI are reserved for a later interface pass; the Agent does not infer a driver from scanner output.

`POST /v1/admin/ups/shutdown` accepts `enabled`, `delay_seconds`, `monitor_username`, and `monitor_password`. Enabling requires a selected UPS and credentials. The delay is 1–86400 seconds. Native `upsmon` sends `ONBATT` and `ONLINE` to `upssched`, which starts or cancels the configured timer. On a remote secondary, timer expiry invokes the fixed JustVoxel emergency poweroff helper. On a local primary, timer expiry invokes the fixed primary FSD helper, which runs `upsmon -c fsd` so NUT coordinates shutdown with secondaries. NUT's critical/FSD handling invokes `SHUTDOWNCMD`, which uses the JustVoxel emergency helper. A `LOWBATT` notification does not trigger an additional scheduled poweroff. The emergency helper calls the confirmed Management API system poweroff endpoint, including player confirmation, so Minecraft uses the existing safe shutdown workflow.

`POST /v1/admin/ups/sharing` accepts `enabled`, `listen_address`, `listen_port`, `client_username`, and `client_password`. Sharing requires a configured local NUT driver. The Agent keeps a localhost listener and adds the requested explicit network listener; it does not change firewalld policy. The deployment must separately approve and configure the intended firewall interface or zone.

The Base image supplies the fixed helpers `/usr/libexec/justvoxel/ups-emergency-poweroff` and `/usr/libexec/justvoxel/ups-primary-fsd`; each requires root and accepts no arguments. Base also installs the narrow sudoers permission allowing the `nut` account to invoke only these two helpers without arguments; the downstream HWS image supplies the `nut` account. The Agent persistently masks local server and driver units for a remote role, and masks `nut-monitor.service` whenever protection is disabled. It unmasks required units before enabling them and uses the stock `nut.target` as the boot anchor. The enumerator service is enabled for a local UPS and run explicitly when configuration changes; its path unit remains disabled. Masks live under `/etc/systemd/system` and survive bootc updates.

The downstream HWS image supplies the NUT package and its stock `/etc/ups` configuration files. On first configuration, the Base Management Agent safely adopts untouched packaged NUT configuration, including files with active stock defaults. It never overwrites modified, unmarked administrator configuration. JustVoxel generates its `/etc/ups` files atomically with an ownership marker. `upsd.conf` and `upsd.users` are root:nut 0640; credentials in `upsmon.conf` and the state JSON remain protected. Source, shutdown, and sharing state live in `/etc/justvoxel` and survive image updates.

The downstream HWS image supplies NUT 2.8.2.1 and its native units. Device discovery selection, mjust and WebUI controls for protection and sharing, firewall policy, and hardware/SELinux validation are later passes.
